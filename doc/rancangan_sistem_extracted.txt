1. Ringkasan Konsep
PrestasiKu adalah platform web umum untuk menemukan, memverifikasi, mendaftarkan, mengelola, dan mendokumentasikan kompetisi serta prestasi pelajar tingkat SLTP/SLTA. Platform bersifat multi-tenant sehingga dapat digunakan oleh banyak sekolah/instansi dengan isolasi data yang ketat.
Cakupan kompetisi: tingkat provinsi dan nasional.
Informasi kompetisi dapat dikumpulkan dari penyelenggara, website resmi, surat/panduan, media sosial resmi, dan berita terkait.
Informasi dari media sosial atau berita tidak otomatis dianggap resmi sebelum proses verifikasi.
Publik dapat melihat kompetisi yang sedang dibuka, bulan berjalan, dan bulan berikutnya.

7. Prestasi dan Verifikasi
Status: Draft → Menunggu Verifikasi → Terverifikasi → Ditolak.
Dokumen pendukung: sertifikat, SK, surat, tautan hasil, atau dokumentasi.
Gunakan public ID seperti PKU-2026-XXXXXX, bukan NIS/NISN.
QR verification hanya menampilkan data publik yang diizinkan.
Profil prestasi publik bersifat opt-in.
8. Privasi Siswa
Profil dan prestasi siswa private by default.
Jangan menjadikan pencarian NIS sebagai akses publik ke seluruh riwayat.
NIS/NISN bukan credential publik.
Gunakan public_id terpisah untuk verifikasi.
Dokumen pribadi disimpan pada private storage.
Akses dokumen menggunakan authorization dan temporary/signed URL.
Minimalkan data yang ditampilkan pada halaman publik.

11. Keamanan Tingkat Tinggi
Laravel Sanctum untuk SPA/API authentication.
Laravel Policies/Gates dan Spatie Permission untuk authorization.
Tenant isolation berdasarkan school_id/tenant_id.
Backend wajib memvalidasi kepemilikan data; jangan percaya school_id dari frontend.
Perlindungan IDOR/BOLA pada seluruh endpoint.
Password hashing Argon2id atau bcrypt.
Password awal 1234 hanya credential sementara; wajib ganti saat login pertama. Untuk produksi lebih aman memakai password acak + activation link.
HTTPS, HSTS, security headers, CORS terbatas, CSRF protection.
Rate limiting untuk login, reset password, API sensitif, dan endpoint publik.
Private file storage, authorization, dan signed/temporary URLs.
Validasi MIME, ekstensi, ukuran, dan isi file.
Audit log untuk aktivitas penting.
Backup terenkripsi, restore drill, dan disaster recovery.
Secret/API key tidak boleh disimpan di repository.
Transaction untuk workflow kritis.
Security testing lintas sekolah untuk memastikan tenant isolation.

19. Kesimpulan
PrestasiKu diarahkan menjadi platform yang menghubungkan discovery kompetisi, administrasi pendaftaran sekolah/siswa, dan pengelolaan rekam prestasi. Keunikan utamanya adalah database kompetisi terverifikasi, eligibility otomatis, multi-tenant sekolah, dynamic form, verifikasi prestasi, QR verification, dan privacy-by-default. Arsitektur ini memungkinkan pengembangan bertahap dari aplikasi operasional sekolah menjadi ekosistem data kompetisi dan prestasi pelajar.
20. Catatan Pengembangan
Dokumen ini adalah rancangan sistem yang dapat diedit. Aturan eligibility, format dokumen, status workflow, field final, kebijakan retensi, dan desain UI perlu difinalisasi sebelum migration production dibuat.
